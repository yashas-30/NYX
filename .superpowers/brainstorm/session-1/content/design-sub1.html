Design Specification: Model Registry DB & Namespace Storage (Sub-project 1)

This spec creates a persistent registry table in SQLite for local models (to store user ratings, favorites, usage stats, and custom presets) and restructures the flat model storage into a namespaced subdirectory hierarchy.

1. SQLite Database Schema (sqlx / pool.rs)

CREATE TABLE IF NOT EXISTS local_models (
    id TEXT PRIMARY KEY,               -- e.g. "bartowski/Llama-3.2-1B-Instruct-Q4_K_M.gguf"
    name TEXT NOT NULL,                -- display name e.g. "Llama 3.2 1B Instruct (Q4_K_M)"
    repo_id TEXT,                      -- HuggingFace repo slug e.g. "bartowski/Llama-3.2-1B-Instruct"
    filename TEXT NOT NULL,            -- e.g. "Llama-3.2-1B-Instruct-Q4_K_M.gguf"
    file_path TEXT NOT NULL,           -- relative path inside models directory
    size_bytes INTEGER NOT NULL,       -- file size on disk
    model_type TEXT NOT NULL,          -- 'text-generation' | 'vision' | 'text-to-image' | 'onnx' | 'pytorch'
    architecture TEXT,                 -- 'llama' | 'qwen2' | 'flux' | 'sdxl' etc.
    context_length INTEGER,            -- max context window size
    has_mmproj INTEGER DEFAULT 0,      -- 1 if a linked multimodal projector exists, else 0
    downloaded_at INTEGER NOT NULL,    -- unix timestamp of installation
    last_used_at INTEGER,              -- unix timestamp of last inference load
    use_count INTEGER DEFAULT 0,       -- total number of server load operations
    rating INTEGER DEFAULT 0,          -- user star rating (1-5)
    is_favorite INTEGER DEFAULT 0,     -- 1 if starred, else 0
    tags TEXT,                         -- JSON array of user tags e.g. '["coding", "fast"]'
    preset_config TEXT                 -- JSON string storing ngl, context, threads overrides
);

2. Directory Structure Restructuring

Currently, all model files sit flat in ~/.nyx-models/models/. We will transition to a task-based namespaced directory layout to prevent file collisions and keep directories tidy.

CURRENT: Flat Layout
~/.nyx-models/models/
├── Llama-3.2-1B-Instruct-Q4_K_M.gguf
├── ae.safetensors (Flux VAE)
├── clip_l.safetensors (Flux text encoder)
├── t5xxl_fp8_e4m3fn.safetensors (Flux encoder)
└── mmproj-model-f16.gguf (vision projector)

3. Improved Directory Scanning & Cache Layer

  • Fast Metadata Lookup: The frontend list_local_models API query will hit the SQLite database table first. This takes under 1ms, eliminating repeated heavy directory reads.
  • tokio::task::spawn_blocking: Synchronous GGUF header parsing (which reads binary GGUF files to extract context size) will be offloaded to Rust's thread-pool to keep the main event loop responsive.
  • Backward Compatibility: The directory scanner will dynamically fallback to checking the flat root directory, indexing any legacy files it finds into the SQLite table and moving them to the namespaces on startup if permitted.
